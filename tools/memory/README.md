# メモリの計測

本番ビルドを Playwright の Chromium で開き、カラムを並べたまま時間を置いて、何がメモリを取っているかを計る（#376）。

## 計る

```sh
vp run build
vp run @streets/web#preview                 # 別の端末で。http://localhost:4173
vp run memory --pubkey <hex か npub>
```

- 開くカラムは、ホーム・通知・自分・自分のリアクション・ユーザー 2 人（`--users <hex か npub>,<hex か npub>`。省くと、投稿も反応も多い公開アカウント 2 人）
- ログインは、公開鍵だけを返す NIP-07 の代わりで行う。署名も暗号化もしないので、計測中にその人の名前で何かが書かれることはない。デッキの同期は読めずに終わるので、リレーに保存したデッキではなく上のカラムで開く
- 流れ：開いて `--settle` 秒（既定 60）待つ → 1 回目のヒープスナップショット → `--minutes` 分（既定 10）まで `--interval` 秒（既定 30）ごとに計る → 2 回目 → 再読み込みして `--settle` 秒待ち、3 回目（`--no-reload` で省く）。再読み込みでは、IndexedDB に溜まったキャッシュを起動時に読み込む分が乗る
- デプロイ済みの環境を計るときは `--app-url` を渡す。画面を見ながら計るときは `--headed`

## 結果

`tools/memory/.out/<日時>/` に書く。

| ファイル | 中身 |
| --- | --- |
| `report.md` | 推移の表と、スナップショットごとの内訳（種類別・名前別の上位） |
| `samples.json` | `report.md` の元の数値 |
| `start.png` | 1 回目の前の画面。カラムが読み込めているかを確かめる |
| `*.heapsnapshot` | Chrome の DevTools の Memory タブで開ける。何が何を掴んでいるか（retained size）はそちらで見る |

数値の読み方。

- **JS ヒープ**は、計る前に GC してからの値
- **画像**は、読み込み済みの `<img>` の画素数 × 4 バイトで見積もった上限。ブラウザが画面の外で捨てた分も含む。「うち縮小なし」は、表示の大きさの 16 倍より多い画素を読んでいるもの
- **プロセス**は、Chrome のプロセスの種類ごとの PSS（Linux だけ）。タブのメモリに近いのは `renderer`、画像のテクスチャなどは `gpu-process` に乗る
- **Nostr のイベントらしいオブジェクト**は、`id`・`pubkey`・`sig` を持つオブジェクトの数。`EventStore` が持っているイベントの数の目安
