# リリースノートの下書き

前のタグから main に入った PR を読み、利用者向けのリリースノート `apps/web/src/releases/<タグ>.md` を下書きして PR にする。人がその PR で直してマージし、タグを打つとリリースになる（`docs/release.md`）。ノートの書式は `apps/web/src/releases/README.md`。

## 手順

1. **範囲を決める**。`git fetch --tags origin` の後、`git describe --tags --abbrev=0 origin/main` で前のタグを得る。タグが無ければ最初のリリース（v1.0.0）で、範囲は v1 の全体。
   完了：前のタグ（または「無し」）と、範囲の終わりのコミット（`origin/main` の先端）が決まっている。

2. **PR を集める**。範囲の first-parent のマージ（`git log --first-parent --merges <前のタグ>..origin/main`）から PR の番号を拾い、`gh pr view <番号> --json title,body,labels,closingIssuesReferences` で中身を読む。
   完了：範囲のすべての PR が「ノートに書く」か「書かない（理由つき）」のどちらかに振り分けてある。書かないのは、利用者から見て何も変わらないもの（リファクタ、テスト、CI、開発者向けの文書、ストーリーだけの変更）。

3. **版の番号を提案する**。利用者から見た変化で決める。
   - major：これまでの使い方やデータが引き継げなくなる（保存したデッキが読めない、なくなる機能がある）
   - minor：新しくできることがある
   - patch：直しただけ
   提案とその理由（決め手になった PR）を人に示し、**人が番号を決めるまで待つ**。
   完了：人が番号を決めた。

4. **下書きを書く**。`apps/web/src/releases/<タグ>.md` を README の書式で書く。
   - 読むのは Streets を使う人。画面で何が変わったかを、Nostr の用語を知らなくても分かる言葉で書く（「kind:10002」ではなく「リレーの設定」）
   - 見出しは `## 新しくできること`・`## 変わったこと`・`## 直したこと` のうち、中身があるものだけ
   - 1 項目は 1 文から 2 文。PR の番号やコードの名前は書かない
   - `date:` はリリースの予定日（言われなければ今日）
   完了：手順 2 で「書く」にしたすべての PR が、どこかの項目に反映されている。

5. **PR を出す**。`release-notes/<タグ>` のブランチを main から切ってノートだけをコミットし、main 宛てに「リリースの準備: <タグ>」の PR を出す。本文には、版の番号の理由、書いた PR、書かなかった PR とその理由を並べる。
   完了：PR の URL を人に渡した。

6. **次を伝える**。PR を直してマージしたら、そのコミットにタグを打つと、プレビュー → 承認 → 本番と進むことを、`docs/release.md` のコマンドとともに伝える。タグは人が打つ。
