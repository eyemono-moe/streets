# 秘密鍵をアプリに渡さない — NIP-07 / NIP-46 のみを許可する

ログイン手段は **NIP-07（ブラウザ拡張）と NIP-46（bunker / リモート署名）に限定**する。nsec の直接入力、およびブラウザ内での鍵生成は**許可しない**。`nostr-login` を採用する場合も、これらの手段は無効化する。

streets は秘密鍵を一切保持しない。署名は常に外部の署名器に委譲する。

## なぜ

これは [ADR-0001](./0001-others-first-self-via-settings.md)（他人が使えることを優先する）と**正面から衝突する決定**である。拡張機能を持たないユーザーの導線を狭めることを承知のうえで、鍵の安全性を優先した。

Web ページへの nsec 貼り付けは Nostr で最悪の慣行であり、**XSS が1つでもあればユーザーのアイデンティティが永久に失われる**。Nostr の鍵にはローテーションもリカバリも存在しないため、この損害は回復不能である。回復不能な損害のリスクを、オンボーディングの滑らかさと引き換えにはしない。

ブラウザ内鍵生成も同様に却下した。生成した鍵の保管責任をユーザーに丸投げすることになり、鍵を失うユーザーを大量に生む。

## Consequences

- 拡張機能を持たないユーザー向けには **NIP-46 (bunker) を案内する導線**が必要。「拡張が無いので使えません」で終わらせてはならない。ADR-0001 を満たすための最低条件。
- nsec を貼ろうとするユーザーが一定数現れる。**なぜ受け付けないのかを説明する UI** が必要。単に入力欄を出さないだけでは不親切。
- 署名は常に外部プロセスへの往復を伴う。署名要求の頻度制御（デッキ保存のデバウンス等）が必須要件となる。
- 「閲覧専用（npub のみ）」モードを後から追加する余地は残す。本 ADR はそれを禁じない。
