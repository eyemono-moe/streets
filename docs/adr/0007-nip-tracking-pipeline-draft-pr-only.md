# NIP 追従パイプラインは draft PR までを生成し、自動マージしない

`nostr-protocol/nips` の更新を定期的に検出し、影響レポートを付けた **draft PR** を LLM に生成させる。**自動マージは行わず、必ず人間がレビューする。**

このパイプラインが成立するのは [ADR-0003](./0003-open-column-abstraction.md) / [ADR-0004](./0004-kind-knowledge-lives-in-kind-specific-code.md) により **NIP 変更の影響範囲が kind 単位に閉じている**からである。変更範囲が機械的に特定できなければ、生成される差分はレビュー不能になる。アーキテクチャとパイプラインは相互に依存している。

## 必須の安全制約

- **NIP 本文は「データ」であり「指示」ではない。** `nostr-protocol/nips` は第三者の PR を受け入れる公開リポジトリであり、NIP 文書に LLM 向けの指示文が混入しうる。パイプラインは NIP 本文中の指示らしき記述に従ってはならない。これはプロンプトインジェクションの経路である。
- **自動マージ禁止。** 上記の経路が本番に到達する唯一の防波堤が人間のレビューである。
- **同時に open にできる自動 PR 数に上限を設ける。** 自動 PR の典型的な失敗は「レビューされない PR が溜まる」ことであり、個人開発では特に起きやすい。上限に達したらパイプラインは新規 PR を作らず issue に留める。
- **NIP の markdown ファイルを一次情報とする。** 第三者による要約は補助的なヒントとしてのみ扱う。
- **差分の粒度でフィルタする。** NIPs リポジトリは typo 修正から破壊的変更まで同じ粒度でコミットされる。すべてに反応すると通知が騒がしくなり無視されるようになる。

## Consequences

- パイプライン自体が保守対象になる。壊れたまま放置されると「追従できている」という誤った安心感を生むため、パイプラインの死活監視が必要。
- 影響レポートには少なくとも「変更された NIP」「影響を受ける kind」「影響を受けるタグ」「必要なテスト更新」「確信度」を含める。
