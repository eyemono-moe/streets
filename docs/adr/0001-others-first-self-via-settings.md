# 「他人が使えること」を自分の利便性より優先する

streets v1 は作者自身が毎日使うメインクライアントであり、同時に他の人にも使ってもらえることを目指す。この2つの目的が衝突したときは **常に「他人が使えること」を優先し、作者自身の使い方は設定・上級設定・キーボードショートカットで確保する**。

## Considered Options

- **自分優先、他人は「壊れていない」まで** — v1 のスコープは最小になるが、新規ユーザーは定着しない。
- **他人優先、自分は設定で逃げる** ← 採用
- **領域ごとに主従を決める** — 実態には合うが、未知の衝突に対して裁定できない。
- **v1 は自分専用、v2 で他人に開く** — v1 が最小になるが、i18n と鍵管理を後から入れるコストが高すぎる。

## Consequences

この決定により、以下は v1 の必須要件に**繰り上がる**（「あとで」にできない）。

- アカウント未所持・リレー未設定の人が到達できる初回オンボーディング
- 英語 UI（i18n 基盤を最初から入れる。後付けは全画面の書き換えになる）
- NIP-07 拡張機能を持たないユーザー向けのログイン導線
- ミュート・センシティブコンテンツ表示制御などのモデレーション機能
- 人間に原因が伝わるエラー表示

反面、以下のリスクを負う。

- 個人開発でありながら射程が広いため、**スコープ管理が最大のプロジェクトリスク**になる。
- 「自分の使い方は設定で逃げる」を無制限に適用すると設定項目の組み合わせ爆発を招く。設定項目の追加には歯止めが必要（別途決定する）。
