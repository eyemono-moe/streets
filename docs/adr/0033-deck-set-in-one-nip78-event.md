# 複数のデッキを 1 つの kind:30078 にまとめて保存する

デッキを名前付きでいくつも持てるようにし、アカウントに保存する（[ADR-0013](./0013-deck-persisted-to-nip78.md) と同じ `d=moe.eyemono.streets/deck`）。形は `version: 3` の `{ decks: [{ id, name, columns }], appearance }` にする。version 2（デッキ 1 つ）は、読むときに id `main` の最初のデッキへ移す。どのデッキを開いているかは端末ごとに違ってよいので、localStorage（`streets.v1.active-deck.<pubkey>`）にだけ置く。

デッキごとに別の `d` タグへ分ける形は取らなかった。分けると、別の端末で別のデッキを同時に触っても競合しない利点はある。一方で、一覧にはあるのに本体を取れないとき（取得中か、無いのか、壊れているのか）の扱いが増え、読み込みの状態も倍になる。

`d` タグを変えずに形を上げると、古い版は新しい形を読めない。それでも古い版は保存の直前にリレー上の最新を取り、知らない版なら上書きせずに止まる（`isRemoteChange`）。そのため新しい形は壊されず、古い版は「同期データを読み取れませんでした」と出すだけになる。

## Consequences

- どのデッキを編集しても、全デッキを暗号化して署名し直す。デッキの数だけ中身は大きくなるが、カラムの定義だけなので数 KB に収まる。
- 別の端末で別のデッキを同時に編集すると、これまでと同じ競合の確認が出る。
- 配色（`appearance`）はデッキではなくアカウントのもので、どのデッキを開いても同じ色になる。
