# モバイルは1カラム表示とし、デッキ編集はデスクトップ専用とする

モバイル幅では**カラムを1つだけ全幅で表示**し、スワイプとタブで左右のカラムに切り替える。表示されるのは**デスクトップで組んだデッキ**であり、**カラムの追加・削除・並び替え・幅変更はモバイルでは行えない**。

書き込み操作は**リアクション・リポスト・短文投稿まで**対応する。画像添付・カスタム絵文字ピッカー・プロフィール編集・各種設定はデスクトップ専用とする。

判定基準は **幅 375px** で上記が成立すること。

## なぜ

マルチカラム UI はモバイルで原理的に成立しない（横に並べられない）ため、「モバイル対応」は必ず何かを捨てる決断になる。「最低限対応する」という表現は判定できないため、上記の具体的な線引きに置き換えた。

外出先で会話に参加できることを最低限とし、デッキを組む作業（時間をかけて行う設定作業）はデスクトップに寄せた。

## Consequences

- **既定デッキが必須要件になる。** モバイルから初めて訪れたユーザーはデスクトップでデッキを組んでいないため、そのままでは空画面になる。これは [ADR-0001](./0001-others-first-self-via-settings.md) と衝突するため、ログイン直後に最初から並んでいるカラム構成（フォロータイムライン・通知など）を用意する。この要件はデスクトップの新規ユーザーにも等しく必要。
- モバイルで「なぜカラムを追加できないのか」を伝える UI が必要。機能が無いことと壊れていることを区別できなければならない。
