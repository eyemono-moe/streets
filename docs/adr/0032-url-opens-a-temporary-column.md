# URL はデッキを置き換えず、一時カラムを開く

`/nevent1…` や `/npub1…` のような URL は、画面全体を切り替えず、デッキの左端に
**一時カラム**を 1 本開く。一時カラムはデッキ（kind:30078）へ保存せず、閉じれば消える。
ヘッダーの「カラムに残す」で、普通のカラムへ昇格できる。

投稿を押して潜るときは、押したカラムの中に一時カラムを開く（戻る／閉じる／別カラムで開く）。
URL から開くときは、どのカラムに出すかを決められないので左端に出す。

ルーティングには `@solidjs/router` を使う。URL とデッキの状態は、URL を正とする。

## なぜ

デッキ型のクライアントでは、並べたカラムが作業机そのものになる。リンクを開くたびに
机を片付けてしまうと、デッキを組んだ意味が無くなる。TweetDeck と deck.blue も、
詳細をカラムの中か追加の列で見せ、デッキの並びは崩さない。

保存しない一時カラムにするのは、リンクを踏むたびにデッキが増えていくのを避けるため。
一方で、開いたものをそのまま使い続けたい場合はあるので、昇格の操作を 1 つだけ持たせる。

左端に出すのは、リンクから来た人が最初に見る場所だから。右端だと、カラムが多いときに
横スクロールしないと見えず、開いたことにすら気づけない。

`@solidjs/router` を使うのは、履歴・戻る・リンクの解釈を自前で持たないため。
[ADR-0020](./0020-no-nostr-library-noble-primitives-only.md) の「ライブラリを使わない」の
射程は Nostr の実装だけで、画面のルーティングは含まない。

## 捨てた案

- **ダイアログで開く**：一番小さく作れるが、スレッドを潜ると重なりが深くなり、
  デッキの他のカラムを読みながら追えない。
- **右のサイドパネル**：デッキは動かないが、画面の幅を常に取る。狭い画面では
  結局全面に出すことになり、一時カラムと同じ扱いになる。
- **URL でデッキごと差し替える**：ブラウザの戻るで元のデッキへ戻れるが、
  リンクを踏むたびに作業机が消える。
