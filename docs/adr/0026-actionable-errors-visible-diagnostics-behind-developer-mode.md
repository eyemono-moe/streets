# 常に見せるのはユーザーが行動できる異常だけとし、診断値は開発者モードの背後に置く

カラムに何か問題が起きたとき、画面に出すものを 2 つに分ける。

| 分類 | 判定 | 出し方 |
|---|---|---|
| **ユーザーが行動できる異常** | それを見たユーザーに取れる行動が存在する | **常に**カラムヘッダのアイコン。押下で「何が起きているか」と「どうすればよいか」 |
| **診断値** | 取れる行動が無い | **開発者モードが有効なときだけ** |

カラムヘッダのアイコンは特定の指標専用ではなく、**そのカラムに起きた異常全般の入口**とする。今は `status.incomplete` しか材料が無いが、レンダラの失敗・未知の kind・購読の拒否など、後から増えるものは同じ場所に集める。

開発者モードは設定で切り替える端末ごとの設定であり、既定は無効。デッキ（[ADR-0013](./0013-deck-persisted-to-nip78.md) で NIP-78 へ保存する）とは別の保存先に置く —— どの端末で開発者として見ているかはアカウントの設定ではない。

## なぜ

**行動に移せない数値を見せても、ユーザーの助けにはならない。** `status.incomplete` の 3 つを行動可能性で仕分けるとこうなる。

- `unreachableRelays` —— そのカラムが**明示的にリレーを指定している**場合だけ行動できる（URL の打ち間違い、落ちたリレーを外す）。Outbox が選んだリレーが落ちている場合、ユーザーには何もできない
- `unroutableAuthors` —— `kind:10002` を公開していない著者。ユーザーには何もできない
- `uncoveredAuthors` —— 接続予算（[ADR-0011](./0011-performance-budget.md) の 30 本）の超過。「カラムを減らす」が一応の行動ではあるが、こちらから促したい行動ではない

常時出す価値があるのは実質 1 つ目のケースだけで、残りは診断値である。**10 カラムで同時に起きると、行動できない警告が画面を埋める。**

**もう一つの理由は、値そのものが説明抜きでは読めないこと。** 縦断スライスの実装者は「`unreachableRelays` は読めば分かるが、`unroutableAuthors` と `uncoveredAuthors` はフィールド名だけでは区別できず、`subscription-manager.ts` のドキュメントコメントを読んで初めて正しく区別できた」と報告している（`docs/design/read-layer-followups.md` 問い4）。作った本人がソースを開かないと区別できない値は、ユーザー向けの表示ではない。

## ADR-0011 の改訂

**これは解釈ではなく改訂である。** [ADR-0011](./0011-performance-budget.md) は Consequences で次のように定めていた。

> **同時接続 30 リレーの上限により、一部の著者の投稿が取得できない状況が発生する。** これを許容するが、**黙って欠落させてはならない** — 取得できていない著者がいることをユーザーに見せる。

このうち「ユーザーに見せる」を、本 ADR により **「ユーザーが行動できる場合に見せる。行動できない診断値は開発者モードの背後に置く」** へ改める。

**「黙って欠落させてはならない」は撤回しない。** 撤回されるのは表示先だけで、次の 3 つは引き続き要件である。

1. **値を計算し続けること。** `status.incomplete` は開発者モードの有無に関わらず常に正しい値を持つ。表示の設定が読み取り層の挙動を変えてはならない
2. **セクションが完全なふりをしないこと。** 欠落があるのに `phase` が `settled` を主張する、`incomplete` を空にする、といった形の隠蔽は禁止のまま
3. **E2E で測定可能であること**（ADR-0011 の中心的な要求）。E2E は開発者モードを有効にして測る。既定で隠れていることは測定可能性を損なわない

この改訂の根拠は実地である。縦断スライスは仕様で「生の数値をそのまま見せる」と決めて実装したが、実際に実鍵で動かした人間の判断は「これはデバッグ用の表示であり、ユーザーが操作で改善できないなら表示する意味がない」だった。ADR-0011 を書いた時点では、その数値が画面に出ている状態を誰も見ていなかった。

## Consequences

- **開発者モードの設定が必要になる。** 端末ごと（localStorage）、既定は無効。設定画面が要る
- **E2E は開発者モードを有効にしてから測る必要がある。** `page.addInitScript` で `localStorage` に `streets.v1.developerMode` を書く。**この ADR の初版は「`e2e/connection-budget.spec.ts` / `section-cap.spec.ts` など既存の spec が診断値を読んでいる」と書いていたが誤りだった**（2026-08-07 訂正）—— どちらも `/debug/v1-section` を見ており、`/debug/` 以下は経路自体が開発者専用なのでこの ADR のゲートの対象外である。二重に隠す意味は無く、隠せばこの 2 つを無意味に壊すだけになる
- **`/v1` のヘッダに並んでいる読み出し**（`connections` / `peakConnections` / `unreachableRelays` / `uncoveredAuthors` / `optimistic-insert-ms`）は、そのまま開発者モード側の表示になる。捨てない —— 実鍵での検証はこれらが読めることに依存している（ルートは A-1 Task 3 で `/v1-preview` から `/v1` へ移設済み）
- **「行動できるかどうか」の判定は今後のカラム種別ごとに増える。** 明示リレーを指定したカラムの `unreachableRelays` が最初の 1 件であり、レンダラ（[ADR-0017](./0017-declarative-renderer-needs.md)）が失敗を報告し始めたら 2 件目を判定することになる。判定を 1 箇所に集め、カラムの実装に散らさないこと。**A-1（2026-08-07）が実際に実装したのはこの 1 件目だけである**（`columnAlerts`、`src/core/deck/column-alerts.ts`）。レンダラの失敗判定（2 件目）はレンダラ登録機構（ADR-0003 の A-2）がまだ無いため未着手のまま
- **[ADR-0015](./0015-section-status-excludes-renderer-fetches.md) は影響を受けない。** あちらが定めているのは `status` に何を含めるかであって、`status` をどう表示するかではない
