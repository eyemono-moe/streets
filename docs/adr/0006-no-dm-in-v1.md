# v1 では DM (NIP-17) を実装しない

streets v1 は DM の送受信を実装しない。UI 上で DM 非対応であることを明示し、専用クライアントを案内する。

理由は実装コストではなく、**中途半端な暗号化実装がユーザーを実害に晒す**こと。DM は 0xchat のような専用クライアントが存在し、そちらに委ねるほうが誠実である。v0 にも DM はないため、[ADR-0002](./0002-v0-parity-before-cutover.md) の機能パリティ要件にも含まれない。

## これは「暗号化を実装しない」という意味ではない

**NIP-44 の復号は v1 で実装する。** NIP-51 のリスト系イベントは公開項目を `tags` に、非公開項目を NIP-44 で暗号化して `content` に持つ。ミュートリスト (`kind:10000`) がこれに該当し、ミュートは [ADR-0001](./0001-others-first-self-via-settings.md) により Must である。

## 却下した理由の詳細

DM を入れると、v1 の設計上の前提が3箇所で破れる。

- **並び順**: NIP-59 gift wrap (`kind:1059`) の `created_at` はメタデータ保護のため意図的にランダム化される。復号するまで本当の時刻が分からず、セクションの並び順が機能しない。
- **性能**: NIP-07 拡張への `nip44.decrypt` 呼び出しがメッセージ1件ごとに IPC 往復を伴う。
- **セキュリティ境界**: [ADR-0004](./0004-kind-knowledge-lives-in-kind-specific-code.md) により kind 固有の知識はレンダラにあるが、復号には署名鍵へのアクセスが必要になる。レンダラが鍵に触る設計の是非を別途決める必要が生じる。

将来 DM を入れる場合、これら3点を先に解く必要がある。「レンダラを1つ足すだけ」にはならない。
